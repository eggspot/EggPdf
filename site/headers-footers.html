Headers & Footers

Add running headers and footers using CSS positioning or @page margin boxes.

Current status

Two ways to add headers/footers: CSS fixed positioning (position: fixed content repeats on every page) and native @page margin boxes (see below), including @page :first/ :left/:right overrides — both support page numbers via counter(page). Tables spanning multiple pages continue correctly, and the <thead> row repeats at the top of every continuation page automatically.

CSS fixed positioning

Use position: fixed to place content at a fixed position on every rendered page. Its containing block is the full physical page, so top: 0 / bottom: 0 reach the literal page edge and can sit inside the page margin.

⚠️
Reserve room for a fixed header/footer with @page margin-top/ margin-bottom — not body margin or padding on a content wrapper. Only @page margins are reapplied on every physical page; a margin/padding on an ordinary flow element is applied once to that element as a whole, so on a multi-page document your header/footer would still collide with body text on every page but the one that element happens to start on. If you're also bottom-pinning a signature/acceptance box (see Page Layout), size the margin to fit both it and the fixed footer together. 
<style>
@page {
    margin-top: 50px;    /* leave room for header, on every page */
    margin-bottom: 40px; /* leave room for footer, on every page */
}
.page-header {
    position: fixed;
    top: 0; left: 0; right: 0;
    height: 40px;  /* must be <= @page margin-top */
    font-size: 10px;
    color: #666;
    border-bottom: 1px solid #e5e7eb;
    display: flex;
    align-items: center;
    padding: 0 20px;
}
.page-footer {
    position: fixed;
    bottom: 0; left: 0; right: 0;
    height: 30px;  /* must be <= @page margin-bottom */
    font-size: 9px;
    color: #999;
    border-top: 1px solid #e5e7eb;
    text-align: center;
    line-height: 30px;
}
body { margin: 0; }
</style>

<div class="page-header">My Company — Confidential</div>
<div class="page-footer">Document Title</div>

Page numbers with counter(page) (works today)

counter(page) and counter(pages) resolve per physical page inside a position: fixed element's content — put them in a ::after (or ::before) rule rather than as literal element text, since a real page number isn't known until the whole document is paginated: 

.page-footer::after {
    content: "Page " counter(page) " of " counter(pages);
}

Each physical page gets its own resolved number — no manual per-page text needed.

Large tables spanning pages (works today)

A <table> taller than one physical page correctly continues onto as many additional pages as it needs — no rows are lost or painted off-page, regardless of table size: 

<table>
  <thead>
    <tr>
      <th>Invoice #</th>
      <th>Date</th>
      <th>Amount</th>
    </tr>
  </thead>
  <tbody>
    <!-- rows continue onto additional pages as needed -->
  </tbody>
</table>

The <thead> row itself repeats at the top of every continuation page automatically — no extra markup needed.

@page margin boxes

Headers and footers can also use standard CSS @page margin box syntax — the same as Chrome's print stylesheet support. All 16 margin-box positions are supported (@top-left/-center/-right, @bottom-left/-center/-right, the four -corner boxes, and the six @left-*/@right-* side boxes), with content (literal strings, counter(page), counter(pages), attr()) plus basic font-size, color, font-family and font-weight styling: 

@page {
    margin: 2cm 2cm 3cm 2cm; /* extra bottom space for footer */

    @top-center {
        content: "My Document";
        font-size: 9pt;
        color: #666;
    }
    @bottom-center {
        content: "Page " counter(page) " of " counter(pages);
        font-size: 8pt;
    }
}
@page :first {
    @top-center { content: none; } /* no header on the first page */
}

@page :first, :left and :right page-selector scoping is also supported, for margin-box content only: :first overrides apply to physical page 1, :left/:right alternate on even/odd pages after that (a margin box with no override for the current page type falls back to the base @page rule). Page size and margin declarations on a selector-scoped rule are not applied — this engine lays out in a single pass, so a different page size per page type isn't supported yet.
